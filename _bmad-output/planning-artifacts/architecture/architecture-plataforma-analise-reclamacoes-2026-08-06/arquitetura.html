Nenhuma afirmação sobrevive sem a frase que a sustenta

Um pipeline que lê reclamações de consumidor e devolve uma fila de prioridade. A regra que organiza tudo o resto: se o modelo marca um risco, ele precisa citar o trecho literal que o prova — e o código verifica a citação sem perguntar ao modelo.

22 invariantes Python · LangGraph 1.2.10 · Gemini 50 reclamações sintéticas

O problema, exatamente

Uma base de reclamações em texto livre é ilegível em escala. A fila de atendimento acaba ordenada por data de chegada, o que trata igualmente uma dúvida de tamanho de vestido e uma cobrança indevida recorrente.

A tentação óbvia é pedir ao modelo que classifique e confiar. Isso falha de um jeito específico: reclamação de consumidor é cheia de indignação retórica — “é uma fraude”, “é um absurdo”, “isso é um crime” — que um classificador ingênuo lê como risco jurídico. Numa base de 50 reclamações reais, a varredura por processo, advogado, Procon, juizado e Código de Defesa do Consumidor retornou zero ocorrências. O que existe é só retórica.

A defesa

sinal: dinheiro_retido
“fui cobrado de uma taxa que eu nunca contratei”
É substring do texto original · sinal mantido
sinal: dinheiro_retido
“o cliente afirma ter sido cobrado indevidamente”
Paráfrase do modelo, não existe no texto · sinal derrubado

A verificação é comparação de string, não julgamento. O modelo não é confiável para auditar a si mesmo; in é.

A forma

AD-7fronteira impura
Um único filtro toca a rede
Apenas analise.py importa o SDK do modelo, e o cliente é construído dentro da função, nunca em escopo de módulo. Impede que a lógica de julgamento fique acoplada à rede — o que tornaria nominal a separação entre “o modelo extrai” e “o código julga”. Verificável por inspeção de import.
AD-16payload
Só id e texto atravessam a fronteira
A empresa fica fora porque nesta base empresa e reclamação estão pareadas ao acaso — um supermercado recebe reclamação de voo cancelado, e derivar produto da empresa produz ranking falso. O título fica fora por um motivo mais duro: o título é o gabarito. A regra determinística classifica por match exato de título, então mandá-lo ao modelo faria o LLM reproduzir a linha de base e esvaziaria a métrica de aceitação. O que não é enviado não pode ser inferido — a defesa é a construção do payload, não uma instrução no prompt.
AD-2evidência
Uma citação falsa derruba o código inteiro
Não só aquele par. Se o modelo apresentou duas citações para o mesmo sinal e uma é fabricada, o sinal cai — inclusive pela citação que passou. Impede confiar na metade que não foi pega, num produto cuja economia declarada é que falso positivo custa mais que falso negativo.
AD-6conservação
Nenhuma reclamação evapora
len(reclamacoes) == len(analises) + Σ ids em falhas, verificado por asserção após o gather. Impede que uma reclamação perdida entre lotes seja indistinguível de uma que nunca entrou.
AD-13aborto
Relatório sobre nada não é relatório
Zero análises encerra sem escrever arquivo. E há uma segunda condição que o contador de análises não pega: se o modelo propôs sinais e 100% deles foram derrubados, o relatório sai marcado como degradado. Cinquenta análises com todas as citações fabricadas produziriam contagem cheia, zero falhas, e um documento de aparência impecável sobre um modelo completamente quebrado.

O contrato de estado

É a única parte do desenho que não é aditiva. Errar aqui converte cache, cascata e checkpoint de plugin em reescrita.

class Sinal(TypedDict):
    codigo: str      # do catálogo de risco
    citacao: str     # literal, piso de cinco palavras
    valida: bool     # default False — não verificado é
                     # indistinguível de reprovado

class Falha(TypedDict):
    ids: list[str]   # reclamações que ficaram sem análise
    causa: str
    no: str

class Estado(TypedDict):
    reclamacoes: list[Reclamacao]
    analises: Annotated[list[Analise], add]
    falhas:   Annotated[list[Falha], add]
    pontuacoes: list[Pontuacao]
    agregados:  Agregados
    caminho_html: str

O desenho anterior tinha sinal_b: list[str] e evidencia: list[str] — duas listas paralelas, sem nada ligando a citação ao sinal. Quando a verificação descobrisse que a segunda citação era inventada, não haveria como saber qual sinal ela sustentava. A regra “derruba o sinal específico” era inexpressável no contrato. Foi o primeiro furo que esta arquitetura fechou.

O que a medição mostrou, incluindo o que não favorece

Antes de construir o pipeline, uma linha de base determinística de seis strings foi escrita para dar uma barra concreta. O classificador com LLM foi medido contra ela na mesma base.

RegraPrecisãoRecallAtende o critério
Categoria de dinheiro retido88,9%84,2%não — precisão
Categoria + Status ≠ Respondida100%68,4%sim
Gemini, vendo apenas o texto livre88,9%84,2%não — precisão

O LLM empata com a regra determinística. Zero divergências nas 50 reclamações — não é empate estatístico, as duas abordagens tomam a mesma decisão em cada linha.

E o empate é menos surpreendente do que parece. Os dois sistemas codificam a mesma resposta, vinda do mesmo humano: a regra casa seis títulos extraídos do gabarito, e o prompt do modelo enumera em prosa as mesmas seis situações. Nenhum dos dois descobriu o critério — ambos o receberam.

A diferença real é estreita, e vale nomeá-la sem inflar. O modelo recebe apenas id e o texto livre, então precisa mapear prosa de consumidor àquelas seis situações; a regra compara uma string com um conjunto. É a única razão pela qual a paridade não é tautológica. O que sobra, na prática: nesta base o LLM é custo sem retorno, e numa base sem títulos padronizados — que é toda base real — a regra determinística não existiria para ser comparada.

O que esta base não exercita

Registrado porque um requisito atendido sobre dado degenerado não está atendido:

  • Sentimento é constante. Negativo em 50 de 50. A leitura de percepção de marca é produzida e informativamente vazia — uma base de reclamações não contém clientes satisfeitos.
  • O ranking de produtos é raso. 18 das 50 identificações caem em fatura, compra, produto, serviço. O ranking ordena palavras, não produtos.
  • Três das cinco parcelas de risco não aparecem. Ameaça explícita: 0 de 50. Elas permanecem no código com um caso de teste construído à mão para cada — o teste prova que o caminho executa, não que a heurística acerta.

Das três leituras que o produto promete, apenas a fila de prioridade é exercida por esta base.

Como a arquitetura foi verificada

A spine passou por reconciliação contra os documentos que a dirigiram e por três revisores independentes. O placar importa menos que a convergência:

Achado críticoConsequência se tivesse passado
Título no payload do modeloO LLM receberia o gabarito da linha de base; a métrica de aceitação deixaria de significar qualquer coisa. Três revisores acharam este furo de forma independente.
select_autoescape(["html"])O seletor casa por extensão e o template termina em .j2: a linha que parece a defesa deixaria o autoescape desligado, e a primeira citação com < quebraria o relatório.
RetryPolicy sem error_handlerRepetição esgotada propagaria a exceção e abortaria o grafo — cinco regras dependiam de um caminho de execução que não existia.

Um revisor adversarial recebeu uma tarefa específica: construir duas unidades que obedecessem todos os invariantes ao pé da letra e ainda assim se construíssem incompatíveis. Encontrou doze pares. Quatro invariantes novos saíram dali — entre eles o que fixa um único escritor por chave de estado, depois de mostrar que na_fila podia razoavelmente pertencer a dois nós diferentes, e que com os dois escrevendo a fila renderizaria vazia sem erro nenhum.
